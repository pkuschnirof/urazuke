# Urazuke — 裏付けの方法

*Urazuke*（裏付け）とは、ある主張が持っている根拠、つまりそれを背後から支えているものを
指す日本語です。動詞の*裏付ける*は「証拠で支える」という意味です。それがこの方法です。

人工知能でソフトウェアを構築し、それが堅牢で、本番運用の準備ができていて、しかも
**プロジェクトのオーナーがコードを一行も読まずに済む**ための方法です。私はこれを、現在
本番稼働している三つの実在のシステムから蒸留しました。昔からあるシステム工学と、それらの
システムが私に見せてくれた「モデルがシステム工学を脆く適用する場所」に支えられています。

著者：Pablo Kuschniroff、Claude Codeの支援による。Creative Commons BY-SA 4.0で公開。
公開ページ：[yujin.app/urazuke](https://yujin.app/urazuke/)。

このフォルダには方法の日本語版が入っています。**スペイン語版が正本であり、日本語版は
翻訳です。** 両者が食い違う場合はスペイン語版が優先され、日本語版が修正されます。

## 三つの別のもの：方法、プロトコル、ツール

これを最初に書くのは、このプロジェクトが抱えるいちばん高くつく誤解だからで、しかも私はそれを
測りました。公開中のサイトを外部のアシスタントに渡したところ、三つを一つの袋に入れてしまい、
全部まとめて「ある製品の物語」だと結論し、私のコードを分析しましょうかと申し出てきたのです。
方法にコードを求めたわけです。三つは性質が違います。はじめに切り分けておきましょう。

**方法がUrazukeであり、それがいま読んでいるこれです。** 何をどの順でやるか、作る者（人でも
モデルでも）に何を要求するか、そしてコードを一行も読まずに、半分ではなく完全に納めたとどう
判断するかを述べます。手順と判断基準、それだけです。手元にあるアシスタントでも、来年出てくる
アシスタントでも、鉛筆と紙と人のチームでも適用できます。ここに全部あり、自由ライセンスです。
二十四の段、その契約、そのプロンプト。

**プロトコルがNAC3であり、これは別のものです。** アプリケーションの画面をプログラムから
操作できるようにする契約で（インターフェイスの各要素が識別子と操作方法を持つ）、同じ手間で、
スクリーンリーダーや音声を使う人も操作できるようになります。エージェントと人が、同じ
インターフェイスを同じ尊厳で渡っていく。方法はこれを一つの目的のための**手段**として使います。
端から端までのテストが画面を自分で歩けるようにすること。方法の条件ではありません。方法の基準は
中立で、第0段にこう書かれています。インターフェイスがプログラムから実行できること、それを
可能にする技術なら何でもよい、と。

**ツールがYujin-Forgeであり、これは一つの実装です。** 方法を自動化し（ゲート、プロンプトの
注入）、プロトコルを話します。Urazukeを適用する*一つの*やり方であって、*唯一の*やり方では
ありません。合わなければ、あるいは要らなければ、方法はそのまま完全なまま残ります。

そしてこれは善意の表明ではありません。**データに入っていて、測れます。** 方法がどんな消費者
にも公開するゲートの機械的な定義は、どのツールも、どのプロトコルも名指ししません。私のもの
でさえも。名前が紛れ込みうるすべての面（ソース、公開される二つのファイル、その索引、生成
される文書）でそれを要求する自動テストがあり、配信中のファイルに対して、誰でも今日、一秒で
確かめられます。

```
curl -s https://yujin.app/urazuke/api/gates.json | grep -o -i -E "forge|nac-?3|yujin" | wc -l
```

**0**が返ります（2026-10-26に計測）。どんなツールでも、どのプロトコルも、ほかのどのツールも
採用せずに、方法のゲートを実装できます。

## 一文で言うテーゼ

AIは方法を中断しない。方法を継続する。業界は二十年前にコードの書き手を信用することを
やめ、コードを読む代わりに証拠を要求することを学んだ。モデルは次の書き手であって、最初の
信用できない書き手ではない。唯一新しいのは、この書き手が証拠までも作り出すということ。
だから証拠は、証拠自身を証明しなければならない。

## 読み方

`ESCALERA_METODOLOGICA.md` から、またはそのHTML版（`../html/ja/`）から始めてください。
見慣れない言葉に出会ったら、用語集が末尾にあります。その後、関心のある段の契約へ。適用
したいならコースのマニュアルへ。あなたが持っているのが空のフォルダではなく、既に動いていて
修正するか成長させなければならないシステムなら、道は `EVOLUTIVO_CORRECTIVO.md` と
マニュアルのパート2です。

## HTMLを再生成する方法

```
node build/build.mjs
```

英語のプロンプトが八つの版で同一であること（契約のものと進化・修正の道のもの）を検証し、
各言語について `ESCALERA_METODOLOGICA.html`、`REFERENCIAS.html`、
`EVOLUTIVO_CORRECTIVO.html`、`MANUAL_CURSO.html`、`MANUAL_CURSO_EVOLUTIVO.html`、
`CAPACITACION_JUNIOR.html`、`TRABAJO_COLABORATIVO.html`、`CONTRATOS_DE_PELDANO.html` を
生成します（スペイン語は `docs/html/`、それ以外は
`docs/html/<言語>/`）。

## 言語

スペイン語が正本です。文書はNAC3の八言語で存在します：スペイン語（`docs/`）、英語
（`docs/en/`）、ポルトガル語（`docs/pt/`）、フランス語（`docs/fr/`）、ドイツ語
（`docs/de/`）、イタリア語（`docs/it/`）、日本語（`docs/ja/`）、中国語（`docs/zh/`）。
各フォルダにはREADME、主文書、参照文書、二十四の契約、進化・修正の道、そしてマニュアル・
コースの二つのパートがあります。モデルへ
のプロンプトは英語の単一の原本で、すべての版で同一であり、その隣に文書の言語への翻訳が
あります。`node build/prompts.mjs --check` は、翻訳がプロンプトを変えていれば失敗します。
名前は翻訳しません。副題は翻訳します：*the evidence method*、*o método da evidência*、
*la méthode de la preuve*、*die Nachweis-Methode*、*il metodo del riscontro*、裏付けの方法、
验证方法。

決定の記録（`../DECISIONES.md`）とコースの計画は、発言をそのまま引用しているため、スペイン
語のみです。
