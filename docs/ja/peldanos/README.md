# 段の契約

段ごとに一ファイル。すべて同じ骨格を持ち、それは意図的です。比較できるように、そして時間とと
もに、読む反射が自動になるように。ヘッダに区間、いつ、形式、規模（必須か比例か）。何のため
か。(1) 必要な文脈、一般的な名前で。(2) プロンプト、**英語**で、それぞれの前に**「プロンプト
を送る前に」**の枠（貼る前にあなたが作り終えていなければならないファイルと材料を、その内容と
最低限の状態とともに）が置かれ、続いてその翻訳、その下にモデルに何を求めているか、なぜ各条項
がそこにあるかの説明。(3) 期待される成果物、その特徴付き。(4) 完全性の検証、あなたがコードを
読まずに行うもの。(5) 警告サイン、段を登り損ねた兆候。

英語のプロンプトは単一の原本で、文書の八つの版で同一です。`node build/build.mjs` がそれら
を `prompts/` に抽出し、どの翻訳もプロンプトを変えていないことを検証します。各プロンプト
に添えられた翻訳はあなたが理解するためのもので、モデルには英語を貼り付けます。

これらは、現在本番稼働している三つのシステムで私が行ったことから書いたもので、このままの
形ではまだ実行していません。最初から最後までこれを使う最初のプロジェクトがいくつかを修正
するでしょう。それは第15段の一部です。契約が実際の事例を引用するときは `[Ref. N]` の印で
[参照文書](../REFERENCIAS.md)へリンクします。手順はきれいなまま、詳細はワンクリック先に
あります。
