# 台阶契约

每级台阶一个文件。所有文件都有相同的骨架，而且是有意的，为了让你能比较它们，也为了让读它们
的反射随着时间变成自动的：标题栏包含阶段、时机、形式和规模（必需或按比例）；用途；(1) 所需
上下文，以通用方式命名；(2) 提示词，**英文**，每条附翻译，下面是我在要求模型什么、为什么每
个条款都在那里的解释；(3) 预期结果及其特征；(4) 完整性检验，你不读代码就能做；(5) 警报信号，
台阶没登好的症状。

英文提示词是单一原件，在文档的八个版本中完全相同；`node build/build.mjs` 把它们提取到
`prompts/`，并检验没有任何翻译改动了它们。每条提示词旁边的翻译是为了让你理解；贴给模型的
是英文。

它们是根据我在三个如今正在生产中的系统里做过的事写成的，我还没有按原样执行过。第一个从头到
尾使用它们的项目会修正其中若干条；那是第 15 级台阶的一部分。当一份契约引用真实案例时，用
`[Ref. N]` 标记链接到[参考资料文档](../REFERENCIAS.md)；流程保持干净，细节一点即达。
