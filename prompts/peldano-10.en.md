## Prompt 1

Every pending item that changes what a user sees or does is closed with its manual test cases written in `docs/MANUAL_TESTS.md`, derived from its acceptance criteria: one case per flow the item touches, with an id, the pending item, the precondition, the numbered steps (what the person does and what they must see), the expected result including a backend effect a person can verify without tools, the test data to use, and an empty execution table (date, who, passed or failed, observation). Write them for a person who does not know how the system is built. Keep the cases of closed items up to date: when a flow changes, its cases change in the same commit. Never mark a case as executed yourself: execution is human. Every manual case also runs once per affected profile, and it is derived from `docs/PROFILE_MATRIX.md` instead of being written by hand: a case run with a single profile is not an executed case (Annex H, anchor 4). At the close of each block add the two human checks no machine replaces: the first-click check, where I name the place I would look for a task and you compare that with the menu, and the real screenshot of the test environment. When you need a decision from me, ask it with the four parts of UX-28 (`docs/ANEXO_HEURISTICAS.md`) and in this order: the data that makes the question necessary, listed; one paragraph of at most five lines that links that data and lets the question be seen; the question itself with its possible answers numbered; and your recommendation. Say it at the technical depth the project declared in `communication_depth` -- `beginner`, `decision_maker` or `technical`; if the project declared none, use `decision_maker`.
